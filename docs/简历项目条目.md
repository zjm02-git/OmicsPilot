## 项目一：基于 LangGraph 的多组学数据分析智能体（GenPilot）

**技术栈**：Python · LangGraph（StateGraph / Checkpointer / interrupt）· LangChain · Chroma · FastAPI · SQLAlchemy · MySQL · PostgreSQL · Redis · Docker · Streamlit

**项目简介**：用户上传表达矩阵与分组表，用一句话描述需求，Agent 自动完成"数据识别 → 质检 → 人工确认 → 差异分析 → 通路富集 → 结果解读 → 出报告"，并把分析偏好写入长期记忆。

**主要工作**

- **上下文预算与降级**：对解读与问答的提示词做 token 预算化管理（6000 / 3000），按"差异结果 > 通路富集 > 基因功能注释"优先级整块裁剪，并在 prompt 中显式声明证据被裁减；模型不可用时降级输出统计摘要而非中断，**LLM 全挂场景端到端由 500 转为 200 并出完整报告**。
- **LLM 调用韧性**：因 OpenAI 兼容 SDK 无逐请求超时，用线程池在调用边界实现硬超时（意图 45s / 解读 120s），叠加指数退避 + 抖动重试与三态熔断；结构化输出解析失败时追加纠错消息重试，仍失败则退回关键词规则路由。**40% 失败率注入下，260 次任务成功率由 55.8% 提升至 90.4%**（调用数 260 → 416）。
- **缓存正确性与可用性**：缓存 key 由"问题文本"改为"归一化问题 + 数据集绝对路径 + 数据集指纹（文件名/大小/mtime 的 sha256）"，**修复了换数据集问同一句话会返回上一份报告的正确性缺陷**；Redis 为主 + 进程内 LRU 兜底、TTL ±10% 抖动防雪崩、`SET NX` single-flight 合并并发同问。**同问重复提交 0.008s 命中（冷路径中位 20.63s），Redis 整体宕机时仍 200 返回（本地兜底 247.8ms）**。
- **降级产出隔离**：状态机新增 `degraded` 标记，模型抖动时生成的降级报告**不写入缓存**，避免一次故障污染 24 小时内所有同问请求；恢复后同问会真实重跑并回填正品（已用故障注入验证）。
- **长任务异步化**：新增 `/analyze_async` 与 `/jobs/{id}` 轮询，任务状态 `queued/running/done/error` 与阶段（质检/差异/富集/解读）可查，避免冷路径 20s+ 阻塞 HTTP 长连接。
- **可观测性与健康检查**：`X-Request-ID` 贯穿日志与响应，`/metrics` 暴露计数器与各路由 P50/P90/P95/P99，`/healthz` 按依赖分级（Redis 挂 → degraded 200，MySQL 挂 → down 503）；统一异常处理器返回可追踪的 `error_type` + `request_id`。
- **测试体系（单测 + 集成）**：**73 个 `unittest` 用例**（65 单测 + 8 Web 集成）覆盖缓存/韧性/上下文/指标/任务/HTTP 契约；集成测试用"真 TestClient + 真 Redis + 真 MySQL + 假模型"跑通 `/analyze → /confirm` 与 `/analyze_async → /jobs/{id}` 两条主链路（假模型仅在测试进程内替换 `get_model`，生产链路仍是真模型）；**7 个模块行覆盖率 88.6%**，`web.py` 由 54.3% 提升至 **83.3%**。自建压测实测**缓存命中路径 32 并发 / 512 请求 0 错误、73.2 req/s、P50 153ms / P95 312ms / P99 340ms**。
- **集成测试反哺出真 bug**：写集成测试时发现 `load_qc_node` 只校验分组列、不校验样本能否与表达矩阵对齐——用户上传缺少 `sample_id` 的分组表时质检照样通过，直到人工确认后才在差异分析里抛 `None of ['sample_id'] are in the columns`，被包装成"会话可能已失效"。已在质检阶段补样本对齐校验并加回归用例（`test_08`）。
- **真模型端到端**：真 DeepSeek + TCGA 真实数据（19938 基因 / tumor 113 vs normal 113）跑完整链路：`/analyze` **3.35s** → `/confirm` **16.07s**（总 **19.42s**），报告 **3676 字**、四章节齐全、`degraded=false`、跑完缓存可命中；脚本 `tools/e2e_live.py` 可复现。
- 数据侧：TCGA-BRCA 真实数据（19938 基因 × 226 样本，113 vs 113）；差异分析向量化（Welch t + BH 校正），富集分析走 GO 注释本地匹配；CSV 解析按 mtime+size 缓存，热读 0.38s → **0.0000s**。

**可被追问且答得出的点**

| 面试官可能问 | 你的答案依据 |
|---|---|
| 90.4% 怎么测的？ | `tools/bench.py::bench_retry_ab`，260 次任务、40% 概率注入 `ConnectionError`，统计最终是否产出报告；对照组 260 次调用，重试组 416 次（重试确实多花了调用） |
| 0.008s 是不是假的？ | 缓存命中路径只做 key 计算 + Redis GET；冷路径 20.63s 是 3 次真 LLM 端到端的中位数（26.40 / 20.63 / 19.01） |
| 降级报告为什么不能缓存？ | 模型挂了只剩统计摘要，内容质量低于正品；若入缓存，24h 内所有同问请求都拿到残缺报告。用 `degraded` 标记 + `cache_skip_degraded_total` 计数验证 |
| single-flight 怎么实现？ | `SET lock:{key} NX EX 60`，抢到算，抢不到 `wait_for` 轮询结果；等待超时（180s）自己兜底重算，宁可重复不挂死 |
| 覆盖率 88.6%，剩下 11% 是什么？ | `web.py` 已到 83.3%，缺口主要是真模型分支与异常兜底（`unhandled_exception_handler`、任务 error 态等）；真实链路由 `tools/e2e_live.py` 单独验证。说清"哪块没测、为什么"比刷数字可信 |
| 集成测试里的假模型算不算造假？ | 不算。它只在测试进程内 `mock.patch("omics_agent.nodes.get_model")`，生产代码零改动；同一条链路另有 `tools/e2e_live.py` 用真模型跑通（19.42s / 3676 字 / 四章节齐全） |
| 为什么不用 Celery/RabbitMQ？ | 当前异步用线程池任务表已满足（4 worker + 状态查询）；单机单进程引入 MQ 只增复杂度。技能栏写"了解"，不写"使用" |

## 项目二：基于 LangChain 的多工具 Agent 智能体

> 这个项目本轮**没有改代码**，所以下面只在你能自证的技术范围内改写。带 ⚠️ 的两条是 AI 建议里值得做、但**目前还没实现**的，做完再加。

**技术栈**：Python · LangChain（`create_agent`）· Streamlit · 多工具编排 · Function Calling

**主要工作（可直接用）**

- **工具注册与调用**：注册 7 个工具（天气、位置、用户信息、RAG 总结、外部数据等），通过 `bind_tools` 绑定为 Function Calling；模型按问题自动决定调用哪个工具、是否串联多次调用。
- **四流式路由**：按问题类型路由到"普通问答 / 工具调用 / RAG / 个人报告"四条流程，用 `yield` + `stream` 实现打字机效果，首字节延迟明显低于一次性返回。

**建议补的两条（做完再写进简历）**

- ⚠️ **工具调用兜底**：Function Calling 参数解析失败时追加纠错消息让模型自我修正重试一次，仍失败则回退到"追问用户补参数"，避免整轮会话崩掉。
- ⚠️ **上下文裁剪**：多轮对话超长时按"最近轮次 + 与当前问题相关性"裁剪历史，而不是简单截断。

## 措辞对照（原句 → 改法）

| 原来 | 改成 | 为什么 |
|---|---|---|
| 基于 LangGraph Checkpointer 实现状态持久化 | 基于 LangGraph Checkpointer 实现状态持久化，**模拟网络中断后断点恢复成功率 100%**（8 次注入，0 次重复计算） | 有结果才是工程；⚠️ 括号里的数字要你自己跑一遍确认再写 |
| Redis 缓存 24 小时过期 | Redis 缓存 + **TTL ±10% 抖动防雪崩 + 进程内 LRU 降级 + single-flight 合并并发计算** | 从"用了什么"变成"防住了什么" |
| 用户上传数据 → 识别角色 → 零代码适配 | 对任意 CSV 做**动态 Schema 推断**（按列 dtype / 取值分布识别表达矩阵、分组表、注释表），支持 3 类表 × N 种列名写法 | 具体可验证，比"零代码"可信 |
| 四流程...yield + stream | 四流式路由 + **首字节延迟对比** | 数字缺失就补测，补不了就删 |

> 关于"断点恢复 100%"这条：`InMemorySaver` 重启进程必丢；只有 `USE_POSTGRES=true` 下才成立。**写之前先跑一次进程重启验证**，否则面试官让我现场演示就露馅。
