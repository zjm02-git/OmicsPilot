# 工程化升级说明（v2.0 → v3.0）

> 升级目标：把"能跑通的 AI 应用"补成"跑不崩的服务"。所有数字均为本机真实测量，可由 `tests/`、`tools/bench.py`、`tools/coverage_report.py` 复现。

## 一、改造前的问题（都有证据，不是猜测）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **缓存 key 只哈希问题文本**，不含数据集 → 换个数据集问同一句话，返回上一个数据集的报告 | `web.py` 原第 200 行 `hashlib.md5(asg.user_request)` |
| 2 | 差异分析主路径的报告在 `/confirm` 才生成，`/analyze` 从不写缓存 → **缓存永远命中不了** | 端到端实测：同问第二次仍走全流程 |
| 3 | Redis 单点：挂了直接抛异常 | 无 try/except 包裹 `redis_client.get/set` |
| 4 | TTL 固定 24h，无抖动、无 single-flight → 雪崩 + 击穿 | 原 `set(..., ex=24*3600)` |
| 5 | `get_model()` 写在 `structured_output_call(...)` 实参位 → 构造期异常不进入重试/降级 | LLM 全挂时 `/analyze` **500**，栈指向 `nodes.py:159` |
| 6 | `interpret` / `qa` 把证据整段拼 prompt，无预算 | 5 张卡片各截 500 字直接拼接 |
| 7 | 长任务同步阻塞 HTTP（冷路径 20-27s） | 前端只能干等 |
| 8 | 无 `/healthz`、无指标、无测试、无压测 | — |

## 二、新增模块

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `omics_agent/resilience.py` | LLM 调用韧性 | 线程池硬超时（`ChatDeepSeek` 无 per-request timeout，只能在调用边界包）、指数退避 + 抖动重试、三态熔断（closed/open/half_open）、结构化输出失败追加纠错消息重试、关键词规则兜底路由 |
| `omics_agent/context.py` | 上下文预算 | CJK 按 1 字/token、其余 /3.5 粗估；按优先级整块丢弃 + 按比例截断；**绝不丢掉最后一个块**（改由截断保证有证据） |
| `omics_agent/cache.py` | 缓存层 | Redis 主 + 进程内 `TTLCache` 兜底；TTL ±10% 抖动；`SET NX` single-flight（并发同问只算一次，其余等待复用）；key = 版本 + 归一化问题 + 绝对路径 + 数据集指纹 |
| `omics_agent/dataio.py` | 数据 IO | CSV 解析缓存（按 `abspath + mtime_ns + size` 失效，返回只读共享对象）；`dataset_fingerprint` 用文件名+字节数+mtime 的 sha256 |
| `omics_agent/jobs.py` | 异步任务 | 线程池注册表、`queued/running/done/error`、`progress()` 经 contextvar 上报阶段、TTL 淘汰 |
| `omics_agent/metrics.py` | 可观测性 | 计数器 + 环形采样 P50/P90/P95/P99、请求 ID 贯穿（contextvar）、单例 `METRICS` |

## 三、业务代码改动

**`web.py`**

- `.env` 提前到所有 `os.getenv` 之前（原来 `REDIS_HOST`/`SECRET_KEY` 实际没读到）；`SECRET_KEY` 缺失退化为进程级随机密钥并告警。
- 缓存：`build_key()` 含数据集指纹；命中走 `get_source()` 标记来源；未命中抢 `inflight` 锁；抢不到 `wait_for` 复用；降级时走 `use_cache=False` 绕过。
- **降级报告不入缓存**：`_run_and_cache` 与 `/confirm` 回填都判断 `degraded`，命中则 `cache_skip_degraded_total` 记账（一次模型抖动不该污染 24 小时的所有同问请求）。
- 缓存命名空间 `v2 → v3`：语义变了，旧条目自然失效，不用手工清 Redis。
- `/analyze_async` + `/jobs/{job_id}`：立刻返回 job_id，前端轮询阶段与结果。
- `/healthz`：redis 挂 → `degraded`(200)，mysql 挂 → `down`(503)。
- `/metrics`：计数器 + 各路由分位耗时 + 缓存/任务/CSV 缓存快照。
- 上传加固：扩展名白名单（`.csv/.tsv/.txt`）、1MB 分块限量（默认 200MB）、文件名净化、失败清理目录；`dataset_path` 强制落在 `data/` 内（含跨盘符 `commonpath` 抛 ValueError 的处理）。
- `@app.exception_handler(Exception)` 统一兜底，返回带 `error_type` + `request_id` 的 JSON（`request_id` 经 `request.state` 传递，contextvar 在中间件退出时已被重置）。
- `/confirm` 续跑加轮数上限（原来是无界 `while`）。

**`nodes.py`**

- 意图解析三级梯度：结构化输出 → 纠错重试 → 关键词规则；`get_model()` 单独 try，构造失败也能降级。
- `interpret` / `qa` 走 `fit_blocks` 预算（6000 / 3000 token），并把"被裁掉的部分"写进 prompt 让模型知道证据不全。
- 模型彻底不可用时降级出报告（标注"模型解读暂不可用"并附统计原文），而不是 500。
- 所有 CSV 读取换 `read_csv_cached`；数行数从整表解析改成 `usecols=[0]`。
- 各节点补计时：`diff.compute_ms`、`enrichment.compute_ms`、`llm.interpret_ms`、`rag.retrieve_ms` 等。

**`omics_agent/state.py`**：新增 `degraded` / `degraded_stages`，降级语义进状态机而不是靠字符串匹配。

## 四、实测数据

### 4.1 缓存

| 场景 | 结果 |
|---|---|
| 同问同数据第二次提交 | **0.008s**，`from_cache=true`，`cache_source=redis`，报告与首次逐字一致 |
| 冷路径（真 LLM，3 次） | 26.40s / 20.63s / 19.01s，**中位 20.63s**，报告 4420 / 4073 / 3814 字，`all_cold: true` |
| 换数据集问同一句话 | key 不同，返回该数据集自己的结论（原 bug 已修） |
| Redis 整体宕机 | **200**，`from_cache=true`，`cache_source=local`，247.8ms，报告完整 |
| 降级报告 | 不写缓存（`cache_skip_degraded_total` 0→1）；恢复后同问必须重跑，产出正品后才回填（`cache_write_total` 0→1） |

### 4.2 韧性

| 实验 | 结果 |
|---|---|
| 重试对照（40% 注入失败，260 次） | 无重试 **55.8%**(145/260) → 有重试 **90.4%**(235/260)，代价 260→416 次调用 |
| 模型全挂 `/analyze` | 修复前 **500** → 修复后 **200**，意图降级为关键词路由；`/confirm` 200、降级报告带说明 |
| 熔断 | 2 次失败后 `state=open` 且拒绝调用；恢复窗口后 `half_open` |

### 4.3 吞吐（缓存命中路径）

32 并发 / 512 请求：**0 错误**，7.0s 完成，**73.2 req/s**，P50 153.5ms / P90 237.1ms / **P95 312.0ms** / P99 339.8ms / mean 164.4ms。

## 六、明确没做的事（面试要能解释"为什么不做"）

1. **没引入 RabbitMQ / Celery**：当前异步已由线程池任务表满足（4 worker + 任务状态查询），单机单进程场景引入 MQ 只增加部署复杂度而无可观测收益。技能栏写"了解"，不写成"使用"。
2. **MySQL 历史表没加乐观锁**：写入是一次性插入、无并发更新同一行，锁只会增加无谓复杂度。需要的是"同一 thread_id 的 confirm 幂等"，已由 `MAX_RESUME_ROUNDS` + 状态机防住。
3. **没写 pytest / CI**：本机无外网、沙箱不能写 `site-packages`，`pytest` 装不上；改写成 65 个 `unittest` 用例，等价覆盖。CI 未接（陈述事实，不美化）。
4. **前端未适配 `degraded` 字段**：后端已透出，Streamlit 仍需加一条"本次结果为降级产出"的提示。
5. **`qa` 的向量检索依赖 bge-m3 冷启动（约 1.9s）**：没做模型常驻/预热，靠惰性加载 + 精确查名兜底。
